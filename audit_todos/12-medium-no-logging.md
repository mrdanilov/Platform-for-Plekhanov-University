# 12 · 🟡 Логирование не настроено вообще

**Severity:** Medium — прод-инцидент не расследуется
**Статус:** ⬜ не начато · **Оценка:** ~30 мин
**Зависит от:** `01` (иначе снова появится «тихое» изменение данных)

## Где

- `config/settings.py` — блока `LOGGING` нет
- Во всём коде **ни одного** вызова `logger` (проверено grep'ом: `logging.`/`logger`/`LOGGING`
  — 0 совпадений в `schedule/`, `config/`)
- `ImportLog` (`schedule/models.py:244`) — единственный след событий, и он пишется только
  при **успешном** импорте (`views.py:669-673`)

## Что не так

Единственный след импорта — запись в `ImportLog`. Неудачные импорты, 500-е ошибки,
таймауты, блокировки SQLite остаются без следа. Для приложения, чьё основное действие —
массовая перезапись расписания, вопрос «кто и когда сломал расписание» не имеет ответа.

Дополнительно: даже успешный импорт сейчас не логируется при сбое в `_log_import`
(запись вне транзакции импорта — если она падает, данные уже применены, а следа нет).

## Направление фикса

1. Добавить `LOGGING` в `config/settings.py`: консоль-обработчик, формат с `asctime`,
   `levelname`, `logger`, `message`. Уровень через env (`DJANGO_LOG_LEVEL`).
2. Добавить `request_id` (django-request-id или свой middleware) — чтобы связать
   логи одного запроса; сейчас контекста для дебага нет вообще.
3. Логировать события импорта явно, а не только успех:
   - начало импорта (имя файла, user, dry_run/apply);
   - итог с перечислением `errors`;
   - исключения вокруг `import_workbook`.
4. **Не** логировать секреты и PII: `uploaded_name` допустим (уже пишется в `ImportLog`),
   но содержимое файла, пароли и контакты — нет.
5. Рассмотреть перенос `_log_import` внутрь транзакции импорта (`on_commit`), чтобы
   успешная запись и лог были согласованы.

## Критерии приёмки

- [ ] `LOGGING` настроен, уровень управляется env, формат содержит время и имя логгера.
- [ ] Неудачный импорт оставляет запись в логе с номером строки/текстом ошибки.
- [ ] Каждый запрос имеет коррелируемый `request_id`.
- [ ] В логах нет содержимого файлов, паролей и контактов преподавателей.
- [ ] `python manage.py check` не ругается на конфигурацию логирования.

## Проверка

```bash
DJANGO_LOG_LEVEL=DEBUG python manage.py test schedule
python manage.py check --deploy
```

## Откат

Реверт `settings.py` (+ `views.py`, если переносится `_log_import`). Миграций нет.
