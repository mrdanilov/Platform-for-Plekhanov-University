# 15 · 🟡 `Substitution.clean()` не вызывается при программном create

**Severity:** Medium — замена может «потеряться» молча, без ошибки
**Статус:** ⬜ не начато · **Оценка:** ~20 мин
**Зависит от:** ничего

## Где

`schedule/models.py:211-215`:

```python
def clean(self):
    if self.lesson_id and self.date and self.lesson.day != self.date.weekday() + 1:
        raise ValidationError({'date': 'Дата замены должна совпадать с днём недели занятия.'})
```

Вызывается только через `full_clean()`, то есть **только в админке** (ModelForm).
Программное создание (`Substitution.objects.create`) правило не проверяет.
Проверено: `Substitution.objects.create(lesson=<занятие в понедельник>, date=2026-01-05)`
проходит без ошибки.

## Почему это опасно

`grid.build_grid` подставляет замену по ключу `(lesson_id, date.isoweekday())`
(`grid.py:101`). Если дата замены не совпадает с днём недели занятия, замена просто
**не находится** — занятие показывается без пометки «замена», молча. Тот же механизм
в `views._teacher_lessons` (`views.py:90-100`): «ушедшие» занятия считаются неверно,
и расписание преподавателя содержит то, чего быть не должно.

Ошибка необратима без ручного разбора: UI её не показывает.

## Направление фикса

1. Добавить ограничение на уровне БД, а не только в Python. SQLite/PostgreSQL не умеют
   проверку «день недели», поэтому полноценный CHECKConstraint невозможен; варианты:
   - хранить рядом `day` (день недели занятия) и проверять `date.weekday()` в constraints
     через `Check` с арифметикой — SQLite不支持 `strftime` в CHECK, PostgreSQL умеет;
   - сделать согласованность следствием логики: сохранять замену с ключом
     `(lesson_id, day)` и вычислять дату из недели — тогда ошибка конструктивно
     невозможна;
   - как минимум — `full_clean()` во всех точках создания.
2. Проверить существующие записи в БД на нарушения и починить (их сейчас 0, но после
   начала работы — может быть иначе).
3. Добавить тест на программный create с «неправильным» днём недели.

## Критерии приёмки

- [ ] Программное создание замены с неверным днём недели падает (или данные не позволяют
      такой ситуации).
- [ ] Админка по-прежнему даёт ту же понятную ошибку валидации.
- [ ] `grid.build_grid` находит замену для любой корректно сохранённой записи.
- [ ] Есть тест, фиксирующий инвариант.
