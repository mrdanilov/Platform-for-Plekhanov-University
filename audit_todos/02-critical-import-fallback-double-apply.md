# 02 · 🔴 Fallback-разбор применяет импорт дважды

**Severity:** Critical — БД остаётся в смешанном состоянии из двух источников
**Статус:** ✅ готово · **Оценка:** ~20 мин
**Зависит от:** `01` · **Блокирует:** `06`

## Где

`schedule/excel.py:461-477`:

```python
grid_result = import_grid(data, filename)
if not grid_result.errors:
    return grid_result
flat = import_schedule(data, filename, dry_run=dry_run)   # ← grid уже закоммичен
if flat.ok:
    flat.warnings.insert(0, 'Файл разобран как плоская таблица.')
    return flat
return grid_result
```

## Что не так

Комментарий в коде гласит «пробуем второй разбор», но `import_grid` к этому моменту
**уже закоммитил свою транзакцию**. Откатить и «попробовать иначе» невозможно:
- если flat-разбор тоже падает, пользователю показывают ошибки от `grid_result`,
  а в БД уже лежит часть записей от grid-разбора;
- если flat-разбор успешен, данные оказываются записаны дважды, из двух источников.

## Почему это опасно

`import.html:96` показывает пользователю блок «Ошибки — файл не применён». Это прямое
ложное утверждение: часть данных применена. Дальнейшее «исправь файл и загрузи
заново» не помогает — импорт это upsert, удаления нет (задача `06`), и смесь
старых/новых записей сохраняется.

## Направление фикса

1. Обернуть обе ветки в одну внешнюю `transaction.atomic()` на уровне `import_workbook`.
2. Перед fallback вызвать `transaction.set_rollback(True)` (savepoint-подход), чтобы
   grid-парсер не оставлял следов, если flat-парсер сработает лучше.
3. В `ImportResult` добавить поле, отражающее, какая ветка сработала, и выводить его
   в UI (`import.html`) — сейчас это видно только по косвенному тексту warning'а.
4. В тексте ошибок различать «ни один разбор не удался» и «удалось только частично».

## Критерии приёмки

- [x] Если grid-разбор дал ошибки и сработал flat — в БД нет ни одной записи от grid-ветки.
- [x] Если оба разбора провалились — БД не изменён **вообще** (проверяется счётчиками).
- [x] UI прямо сообщает, какой разбор сработал (сетка / плоская таблица / ничего).
- [x] Блок ошибок не показывается, когда в БД что-то уже записано (либо пишет «частично»).

## Реализовано

- `schedule/importer.py` — в `ImportResult` добавлено поле `source`
  (`'grid'` / `'flat'` / `''`) и свойство `source_label` для UI.
- `schedule/excel.py` — `import_workbook` обёрнут в одну внешнюю
  `transaction.atomic()`; каждая ветка выполняется под своим savepoint.
  Перед fallback вызывается `transaction.set_rollback(True)`, поэтому записи
  grid-ветки откатываются. Плоская ветка тоже откатывается, если вернула
  ошибку, — частичной записи не остаётся. Отчёт об отсутствии результата
  собирает `_both_failed`. CSV-путь проставляет `source='flat'`.
- `schedule/templates/schedule/import.html` — выводит строку «Разбор: …» и
  при пустом `source` пишет «Файл не применён — ни один разбор не удался».
- `schedule/test_excel.py` — `ImportWorkbookFallbackTests` (fallback без
  grid-записей, откат при двух ошибках, dry_run, CSV) и `ImportSourceUiTests`
  (UI-сообщения).
