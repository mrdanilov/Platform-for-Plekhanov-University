# 04 · 🔴 Проект не находится под контролем версий

**Severity:** Critical — нет истории, отката, ревью и расследования инцидентов
**Статус:** ⬜ не начато · **Оценка:** ~10 мин
**Зависит от:** ничего · **Блокирует:** откат для **всех** остальных задач

## Где

Корень проекта `/Users/farkhodov/Desktop/timetable`:

```
$ git rev-parse --is-inside-work-tree
fatal: not a git repository (or any of the parent directories): .git
```

При этом `.gitignore` уже написан и содержит `.venv/`, `.secret_key`, `db.sqlite3`,
`tmp_import/`, `__pycache__/`, `*.pyc`, `staticfiles/`.

## Что не так

Основное действие приложения — массовая перезапись расписания всего университета
(см. задачи `01`/`02`/`06`). Без истории изменений это означает:
- невозможно откатить неудачный импорт, применённый на проде;
- невозможно установить, кто и когда изменил расписание/настройки безопасности;
- README и `.gitignore` правятся безвозвратно;
- правки безопасности (например `TRUST_X_FORWARDED_FOR_IP`) не проходят ревью.

Отсутствие git — причина, по которой баг `01` прожил: сравнить «было/стало» нечем,
и первый коммит зафиксирует уже сломанное состояние.

## Направление фикса

1. `git init`, `.git add -A`, первый коммит с описанием текущего состояния
   (**до** начала волны 1 — чтобы был чистый baseline).
2. Проверить, что в индекс не попали `.secret_key`, `db.sqlite3`, `.venv/`
   (`.gitignore` их покрывает — проверить `git status --ignored` до коммита).
3. Pre-commit хук: `python manage.py check` + `python manage.py test schedule`.
4. Долгосрочно: цель на CI (GitHub Actions и т.п.) — прогон тестов на каждый push.
   Сейчас CI нет вообще, тесты запускаются только вручную.

## Критерии приёмки

- [ ] `git log` содержит хотя бы один коммит со всем исходным кодом.
- [ ] `git ls-files` не содержит `.secret_key`, `db.sqlite3`, `.venv/`.
- [ ] `git status` чистый после коммита.
- [ ] Правка любого файла видна как отдельный диффом.
- [ ] Pre-commit не даёт закоммитить код, падающий `manage.py test`.

## Проверка

```bash
git init
git status --ignored        # убедиться, что секреты и БД игнорируются
git add -A && git commit -m "Baseline: текущее состояние до волны фиксов"
git ls-files | grep -E "secret_key|sqlite3|\.venv"   # должно быть пусто
```

## Откат

`rm -rf .git` (до первого пуша). После пуша — восстановление через remote.
