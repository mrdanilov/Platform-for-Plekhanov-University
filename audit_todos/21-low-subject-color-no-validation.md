# 21 · ⚪ `Subject.color` без валидации → CSS-инъекция

**Severity:** Low — требует прав staff; XSS не даёт (Django-автоэскейп работает)
**Статус:** ⬜ не начато · **Оценка:** ~10 мин
**Зависит от:** ничего

## Где

- `schedule/models.py:48-51` — `color = models.CharField('Цвет', max_length=7, default='#e3f2fd', help_text='HEX-цвет подложки, например #e3f2fd')` — валидации формата нет, есть только подсказка в help_text
- `schedule/templates/schedule/_block.html:73` — `style="background: {{ cell.subject.color }};"`
- `schedule/templates/schedule/_cards.html:37` — то же
- `schedule/templates/schedule/day.html:47` — `background:{{ row.color }}`
- `schedule/admin.py:66-72` — `swatch` через `format_html(...)` (здесь экранирование корректно)

## Что не так

Значение попадает внутрь `style="..."` из значения в БД. Django-автоэскейп не даёт выйти
из атрибута (кавычки экранируются), поэтому XSS/инъекция разметки невозможна. Но
внутри CSS остаётся полная свобода: значение вида `#fff;background-image:url(https://...)`
делает запрос на внешний ресурс при каждом показе расписания — трекинг посетителей
через админ-аккаунт.

## Направление фикса

1. Добавить `validators=[RegexValidator(r'^#(?:[0-9a-fA-F]{3}|[0-9a-fA-F]{6})$')]`
   на `Subject.color`.
2. Проверить существующие записи; `importer._pick_color` уже берёт цвета из фиксированной
   палитры (`importer.py:63-66`) — то есть легитимные данные всегда корректны.
3. Дополнительно: разумно фильтровать/экранировать `style` в шаблонах — выводить цвет
   через `style="background: {{ color }}"` с гарантированно валидным значением, а не
   полагаться только на модель.

## Критерии приёмки

- [ ] `Subject(color='x; font-size:99px').full_clean()` падает с понятной ошибкой.
- [ ] Импорт и существующие записи проходят валидацию.
- [ ] Есть тест на невалидный цвет (в т.ч. через админку).
