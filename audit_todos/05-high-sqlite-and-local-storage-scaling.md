# 05 · 🟠 SQLite + локальный FS + LocMemCache не масштабируются

**Severity:** High — при нескольких воркерах/репликах ломается и защита, и импорт
**Статус:** ⬜ не начато · **Оценка:** зависит от решения (30 мин — single-instance, несколько дней — PostgreSQL)
**Зависит от:** `04`, `08`

## Где

- `config/settings.py:119-124` — `DATABASES`: `sqlite3`, `NAME = BASE_DIR / 'db.sqlite3'`
- `config/settings.py:168` — `IMPORT_TMP_DIR = BASE_DIR / 'tmp_import'`
- `config/settings.py` — `CACHES` не задан → дефолтный `LocMemCache`
- `schedule/throttle.py:6-16` — это уже описано в docstring модуля, но не исправлено
- `config/settings.py` — `CONN_MAX_AGE` не задан

## Что не так

Три инфраструктурных решения завязаны на «одна реплика, один процесс»:

1. **Rate limit `/list/`** живёт в памяти процесса. При 2+ воркерах каждый считает
   запросы отдельно, реальный лимит умножается на число воркеров — перебор букв для
   выкачивания списка преподавателей снова открывается.
2. **`tmp_import` на локальном FS.** Сессия хранит только имя файла (`views.py:640`,
   `views.py:657`). Запрос «Применить импорт» после «Проверить файл», попав на другую
   реплику, не найдёт файл → «файл устарел, загрузите заново».
3. **SQLite** блокирует запись целиком. Подтверждено локально: 4 параллельных импорта →
   `OperationalError: database table is locked` на всех потоках, **0 записей сохранено**.

## Направление фикса

Сначала принять решение, а не чинить наугад.

**Вариант A — Single-instance (рекомендую, если это сайт одного вуза):**
- оставить SQLite;
- ограничить параллельный импорт одним процессом (lock-файл в `tmp_import` или
  advisory-lock на БД), поверх — `timeout` в `OPTIONS` SQLite;
- явно зафиксировать в README: «одна реплика, один воркер», иначе решение неявное.

**Вариант B — несколько реплик/воркеров:**
- PostgreSQL;
- `CACHES` на Redis/Memcached (или django-redis) — иначе rate limit не работает;
- `tmp_import` заменить: либо временное хранилище с явным TTL, либо (проще и надёжнее)
  передавать содержимое файла в один POST — тогда состояние «проверено» держится
  в сессии, а не на диске.

## Критерии приёмки (вариант A, минимум)

- [ ] Два одновременных `apply` не приводят к `database table is locked`;
      второй получает внятное сообщение, а не 500.
- [ ] Импорт с `timeout` при записи даёт предсказуемый отказ, а не частичную запись.
- [ ] В README явно написано ограничение «одна реплика».

## Критерии приёмки (вариант B)

- [ ] `manage.py migrate` проходит на PostgreSQL.
- [ ] Тесты (`manage.py test schedule`) проходят на PostgreSQL.
- [ ] Rate limit срабатывает при нескольких воркерах (проверка двумя процессами).
- [ ] Импорт работает при разных репликах, попадающих на разные хосты.

## Проверка

python manage.py test schedule

## Откат

Вариант B — миграция данных с SQLite на PostgreSQL: `pgloader` или `dumpdata | loaddata`,
плюс откат конфигурации. Откат требует бэкапа (задача `19`).
