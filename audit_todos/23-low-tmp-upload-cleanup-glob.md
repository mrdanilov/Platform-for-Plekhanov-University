# 23 · ⚪ Очистка `tmp_import` только при загрузке, `glob('*')` по каталогу

**Severity:** Low — файлы копятся бессрочно; чужой файл в каталоге будет удалён
**Статус:** ⬜ не начато · **Оценка:** ~15 мин
**Зависит от:** ничего

## Где

- `schedule/views.py:584-591` — `_clear_stale_uploads(max_age_hours=6)`
- Вызывается только из `_store_upload` (`views.py:571`), то есть **только при загрузке**
- Противоречие в документации: `schedule/models.py:249` — «файл остаётся во временной
  папке и удаляется через 6 часов»

## Что не так

1. Если после загрузки никто больше ничего не загружает, файлы лежат **бессрочно** —
  обещание «удаляется через 6 часов» не выполняется.
2. `for path in _tmp_dir().glob('*')` + `path.unlink()` — удаляется **любой** файл старше
  6 часов в этом каталоге. Сейчас каталог используется только для загрузок, но это
  скрытая опасность: если туда положит что-то другое (бэкап, временный файл
  экспорта), оно будет удалено без предупреждения.
3. Загрузки содержат расписание с ФИО преподавателей — то есть это персональные данные,
  и «удалить через 6 часов» тут не просто гигиена.

## Направление фикса

1. Убирать только файлы, соответствующие ожидаемому шаблону имени (`uuid4().hex` +
  расширение из белого списка), а не любой файл в каталоге.
2. Добавить отдельную регулярную очистку (cron/Task Scheduler), а не рассчитывать на
   загрузку. Либо — как признано в `05` — вообще не хранить файл на диске.
3. Привести формулировку в `models.py` и README в соответствие с фактическим поведением,
   какое бы оно ни стало.
4. Проверить права на каталог: `BASE_DIR/tmp_import` создаётся через `mkdir` с правами
   по умолчанию (umask) — для персональных данных лучше `0o700`.

## Критерии приёмки

- [ ] Посторонний файл в `tmp_import` не удаляется очисткой.
- [ ] Файлы удаляются по расписанию, даже если новых загрузок нет.
- [ ] Права на каталог — `700`, файлы читаемы только владельцем.
- [ ] Документация соответствует поведению.
