# 07 · 🟠 Нет rate limit на контактной форме и на логине админки

**Severity:** High — неограниченный спам в БД и перебор пароля единственного админа
**Статус:** ⬜ не начато · **Оценка:** ~30 мин
**Зависит от:** `08` (нужен реальный IP за прокси)

## Где

- `schedule/views.py:387` — **единственный** вызов `throttle_ok` во всём коде (`picker_list`)
- `schedule/views.py:257-302` — `university_contact`, без ограничения частоты
- `config/urls.py:8` — `/admin/`, стандартный Django admin без блокировок
- `schedule/captcha.py` — арифметическая captcha, обновляется по `?refresh=1` без счётчика

## Что не так

**Контактная форма.** Rate limit есть только у `/list/`. На форме стоит только captcha.
Ответы арифметические, операнды 2..9, три операции — пространство ответов маленькое.
`?refresh=1` выдаёт новый вопрос без ограничений. Проверено: **20 неверных ответов подряд
дали 400, блокировки нет**. Итог — неограниченный рост `ContactMessage` (лимита на таблицу
нет) и **никакого уведомления модератору**: ни email, ни флага «прочитано», только
список в админке (`ContactMessageAdmin`). Заметка с формы «протухнет» незамеченной.

**Логин админки.** Админка даёт полный контроль над расписанием (CRUD всех моделей + импорт).
Django admin из коробки не имеет ни rate limit, ни блокировок, ни 2FA. В текущей БД
`auth_user` — **1 строка**, то есть перебирается единственный аккаунт без ограничений.

## Направление фикса

1. `throttle_ok` по IP на POST `/university/contact/` — например 5 попыток в час
   (по аналогии с существующей логикой в `throttle.py`, ключ вида `contact:{ip}`).
2. Rate limit на `/admin/login/` — можно на уровне nginx (`limit_req`) либо через
   middleware; в nginx надёжнее, это уже отмечено в README.
3. Для контактов: флаг `is_read` / модераторская очередь + уведомление на почту
   (`ContactMessage` → письмо). Это отдельная полезная правка, но она уже за рамками
   «только защиты».
4. Долгосрочно: `django-axes` или аналог для защиты админки от перебора.

## Критерии приёмки

- [ ] 6-й POST на `/university/contact/` с одного IP за час получает 429 (или эквивалент).
- [ ] Гость, превысивший лимит `/list/`, по-прежнему получает 429 (регрессия не сломана).
- [ ] Ключ лимита считается по IP, полученному по правилам `client_ip` (учитывает
      `DJANGO_TRUST_XFF`).
- [ ] При `DJANGO_TRUST_XFF=1` и корректно переписанном nginx-заголовке лимит работает;
      при выключенном — считает по `REMOTE_ADDR` (текущее поведение).

## Тест

Расширить `schedule/test_throttle.py`: контактная форма (с корректной captcha) +
сценарий превышения лимита; проверить, что при включённом лимите успешная отправка
по-прежнему работает в пределах лимита.

## Проверка

```bash
python manage.py test schedule
```

если не вводится `is_read` (тогда — миграция на `ContactMessage`).
