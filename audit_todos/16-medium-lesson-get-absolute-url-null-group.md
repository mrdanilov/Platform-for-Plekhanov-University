# 16 · 🟡 `Lesson.get_absolute_url()` падает при `group=None`

**Severity:** Medium — 500 в админке на реальных записях
**Статус:** ⬜ не начато · **Оценка:** ~10 мин
**Зависит от:** ничего

## Где

`schedule/models.py:176-177`:

```python
def get_absolute_url(self):
    return reverse('schedule:group_detail', args=[self.group_id])
```

Поле `group` — nullable (`models.py:123-126`), и такие записи реально создаются:
`excel.py:428` создаёт `Lesson` без группы, когда ячейку не удалось разобрать
(такие записи накапливаются как «мусорные» с `raw_text`).

Подтверждено:
```
Lesson.objects.create(subject=s, day=2, lesson_time=lt).get_absolute_url()
-> NoReverseMatch: Reverse for 'group_detail' with arguments '(None,)' not found
```

## Почему это опасно

Клик «Посмотреть на сайте» на таком занятии в админке → 500. В текущей БД таких записей
нет (`group_id` заполнен у всех 120), но импорт сетки их создаёт регулярно — это часть
штатного разбора нераспознанных ячеек.

## Направление фикса

1. `get_absolute_url` должен корректно обрабатывать `group_id is None`. Варианты:
   - возвращать `''`/ссылку на фильтр по преподавателю/паре, если она есть;
   - возвращать URL страницы «На сегодня» как безопасный fallback.
2. Дополнительно: в админке для таких записей лучше показывать понятное объяснение
   («занятие без группы, создано импортом нераспознанной ячейки»), а не битый URL.
3. Решить, что с такими записями делать в принципе: либо чинить импорт, чтобы группа
   всегда определялась, либо документировать их как «сырые» (это пересекается с `06`).

## Критерии приёмки

- [ ] `get_absolute_url()` не бросает исключение при `group_id is None`.
- [ ] Клик «Посмотреть на сайте» на такой записи открывает рабочую страницу, а не 500.
- [ ] Есть тест на запись без группы.
