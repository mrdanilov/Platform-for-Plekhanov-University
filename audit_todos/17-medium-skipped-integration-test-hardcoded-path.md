# 17 · 🟡 Интеграционный тест с реальным файлом молча выключен

**Severity:** Medium — тест, который поймал бы Critical-баг `01`, не выполняется
**Статус:** ⬜ не начато · **Оценка:** ~15 мин
**Зависит от:** ничего

## Где

`schedule/test_excel.py:17`:

```python
TEMPLATE = 'C:\\Users\\Den\\Documents\\Расписание_как_на_фото.xlsx'
```

`schedule/test_excel.py:209-211`:

```python
if not os.path.exists(TEMPLATE):
    self.skipTest('файл-шаблон не найден')
```

Прогон тестов: `Ran 287 tests ... OK (skipped=1)` — этот единственный тест пропускается.

## Что не так

Единственный тест, работающий с **настоящим** файлом-шаблоном вендора, молча выключен
хардкодом личного пути. Он не выполняется ни на чём, кроме машины автора (и то только
если файл сохранился по этому пути). Именно этот тест дал бы «Проверить файл пишет в БД»
на реальном файле, а не на синтетической книге.

Побочно: хардкод абсолютного пути делает сборку непереносимой (README вообще ориентирован
на Windows).

## Направление фикса

1. Убрать абсолютный путь. Варианты:
   - путь из переменной окружения (`TIMETABLE_TEMPLATE`) + `skipUnless` с понятным
     сообщением;
   - положить обезличенный пример файла в `tests/fixtures/` (предпочтительно: тест
     становится воспроизводимым у всех и в CI).
2. Если файл недоступен — не делать вид, что тест зелёный: `skipTest` допустим, но
   присутствие skip должно быть видно в выводе CI (не подавлять).
3. Дополнительно: этот тест стоит расширить до сквозного сценария «загрузка файла через
   `/import/` в режиме проверки не меняет БД» — прямая защита от `01`.

## Критерии приёмки

- [ ] В репозитории нет абсолютных путей к файлам вне репозитория.
- [ ] Тест с реальным файлом либо выполняется у всех (`fixtures/`), либо явно помечен
      как условный с указанием, что нужно для запуска.
- [ ] `manage.py test schedule` показывает ожидаемое число тестов без «неожиданных» skip.
- [ ] Есть сквозной тест: `check=1` не меняет БД (см. задачу `01`).

## Проверка

```bash
python manage.py test schedule -v 2
```

## Откат

Реверт `test_excel.py`. Фикстуры — новые файлы, удаляются тривиально.
