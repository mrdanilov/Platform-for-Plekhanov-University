# 20 · 🟡 Версия Python не зафиксирована

**Severity:** Medium — сборки могут разойтись по версии интерпретатора
**Статус:** ⬜ не начато · **Оценка:** ~15 мин
**Зависит от:** `04`

## Где

- Нет `pyproject.toml`, `.python-version`, `runtime.txt`, `Pipfile`
- `requirements.txt` — только 3 строки с зависимостями, без указания версии Python
- Локально `.venv/pyvenv.cfg` указывает `C:\Python314` / `version = 3.14.5`

## Что не так

Версия интерпретатора нигде не объявлена, при этом локально используется только что
вышедший мажор (3.14). Ничего в коде не требует 3.14 — значит, выбор случаен, и
следующая машина/сборка может получить другую версию. Различия между 3.12 и 3.14
(например, по поведению `datetime`/deprecation-предупреждения) проявляются уже в
логах и в поведении stdlib, а не в явных ошибках.

Аудит прогонял тесты на **3.12** — всё зелёное (287 тестов), значит 3.12 — безопасная
база для фиксации.

## Направление фикса

1. Добавить `.python-version` (например `3.12`) — работает с pyenv/uv и соответствует
   проверенному прогону.
2. Либо `pyproject.toml` с `requires-python = ">=3.12,<3.13"` и `project.dependencies`
   на месте `requirements.txt`.
3. Прописать версию в README рядом с командой запуска.
4. Зафиксировать версию в CI (после появления CI, см. `04`).

## Критерии приёмки

- [ ] Версия Python объявлена в репозитории.
- [ ] `python --version` из виртуального окружения, созданного по инструкции из README,
      совпадает с объявленной.
- [ ] `python manage.py test schedule` проходит на зафиксированной версии.

## Проверка

```bash
cat .python-version
python --version
python manage.py test schedule
```

## Откат

Удаление файла. Миграций нет.
