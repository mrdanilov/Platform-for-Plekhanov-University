# Расписание вуза

Веб-приложение вместо бумажного расписания на стенде. Преподаватель,
аудитория и группа открывают своё расписание в браузере, сотрудница правит
его через админку без программиста и без Excel.

Django + SQLite. Интерфейс на русском и узбекском. Во фронтенде нет сборки,
npm и внешних библиотек: HTML-шаблоны Django, около двухсот строк
JavaScript и один файл CSS. Внешних ресурсов при работе не грузится ни
одного — приложение целиком работает в локальной сети.

## Что умеет

**Смотреть расписание.** Четыре окна: расписание группы, расписание
преподавателя, чем занят кабинет, что менялось на этой неделе. Плюс
«Сегодня» — весь вуз за один день, с 9:00 до последней пары.

**Различать недели.** Расписание чередуется: на нечётной неделе одни
пары, на чётной другие. Приложение хранит чётность каждой недели и
показывает нужную. Стрелки вверху переключают неделю без перезагрузки.

**Объединять.** Группы, которые ходят вместе, показываются одной карточкой
с кодами через запятую. Две одинаковые пары подряд у кабинета рисуются
одной широкой ячейкой — так же, как на бумажном стенде.

**Править без программиста.**

- Загрузка расписания из файла Excel одной командой. Сначала запускается
  вхолостую: приложение показывает, что собирается записать, и ничего не
  меняет.
- Черновик перед публикацией: сотрудница видит, что получится, и только
  потом публикует. До этого на сайте ничего не меняется.
- Журнал изменений и откат: кто, когда и что поменял, видно списком, и
  любую публикацию можно вернуть целиком.
- Мелкие правки прямо в списке: передвинуть пару, объединить две в одну,
  растянуть занятие на две или три пары подряд.

**Не дать испортить расписание.**

- Дубли в справочниках не появляются: «Лекция» и «Лекция » с разными
  пробелами — это один тип занятия, а не два. То же с кабинетами,
  преподавателями и предметами.
- Растяжка проверяется до применения. Если в ту же пару в ту же неделю
  встал кто-то ещё, приложение скажет об этом и откажется растягивать,
  вместо того чтобы получился двойной урок.
- Две сотрудницы открыли одно занятие — вторая получит предупреждение, а
  не затрётёт правку первой молча.
- Пустое поле означает «не трогать». Чтобы случайно стереть заполненное,
  надо поставить отдельную галочку.
- Вход в админку закрыт снаружи: с чужого адреса страницы входа просто
  нет — ни формы, ни намёка, что она существует.

**Выгружать и печать.** Расписание в Excel и CSV, в том числе по одному
преподавателю. Кнопка «Выгрузка» с паузой в 30 секунд, чтобы файл не
забрали чаще, чем нужно. Печать прямо из браузера, раскладка рассчитана
на лист.

**Для посетителей.** Страница университета с контактами, форма обратной
связи с картинкой-капчой и ограничением частоты попыток.

Мелочи, без которых на старом мониторе не поработаешь: масштаб кнопками,
тёмная тема, читаемый тёмный текст на светлой подложке карточки.

## Логика, на которой всё держится

Четыре решения, из которых следует всё остальное.

**Чётность недели хранится в данных, а не вычисляется из календаря.**
Номера недель вуза и календарные недели не совпадают. Из-за этого занятия
показывались не в те дни, для которых были составлены: 12 октября 2026
года — 42-я календарная неделя, но 7-я неделя семестра. Пока не пришлось
задать дату начала семестра, расписание просто показывалось неправильно.

**Публикация идёт через черновик.** Публичный сайт нельзя испортить
недосмотренной правкой. Сначала предпросмотр, потом сознательное решение,
потом запись в журнал. Это же сделало возможным откат: публикация
хранит снимок «было», и вернуть можно не только последнее действие, а
всю публикацию целиком.

**Файл вуза разбирается осторожно.** В файле вуза в одной ячейке сразу
предмет, тип занятия, должность, фамилия и аудитория, а группы стоят
колонками, каждая пара — «код группы / аудитория». Разбор идёт по этим
правилам; пропущенные строки считаются и показываются, а не теряются
молча. Противоречие в шапке останавливает загрузку: тихая ошибка здесь
означала бы, что занятия показаны не в ту неделю.

**Данные проверяются на входе.** Битый цвет, дубли в справочниках,
конфликт занятий при растяжке, две одновременные правки — всё отсекается
в момент записи. Иначе это всплыло бы через месяц, когда причину уже
не найти.

## На чём сделано

| | |
|---|---|
| Сервер | Django 5.2, Python 3.12+ |
| База | SQLite: один файл, копируется целиком |
| Файл расписания | openpyxl, только чтение `.xlsx` |
| Запуск | waitress на Windows, gunicorn на сервере |
| Фронтенд | без сборки: шаблоны Django, ~200 строк JS, один CSS |
| Проверки | 900+ автотестов: `python manage.py test schedule` |

## Запуск

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt      # Windows: .venv\Scripts\pip
.venv/bin/python manage.py migrate
.venv/bin/python manage.py createsuperuser
.venv/bin/python manage.py runserver
```

Открыть <http://127.0.0.1:8000/>. Данные вносятся через админку.

Показать коллегам по локальной сети:

```bash
python tools/show_lan.py                        # сам найдёт адрес и напечатает ссылку
```
