# Расписание вуза

**Расписание вуза в браузере: загрузка из файла, черновики правок, журнал и откат.**

Веб-приложение вместо бумажного расписания на стенде. Преподаватель,
аудитория и группа открывают своё расписание в браузере, сотрудница правит
его через админку — без программиста и без Excel.

Во фронтенде нет ни сборки, ни npm, ни внешних библиотек: HTML-шаблоны
Django, около двухсот строк JavaScript и один файл CSS. При работе не
загружается ни одного внешнего ресурса — приложение целиком работает в
локальной сети вуза.

## Задача

Расписание висело на бумаге. Его правили вручную, изменения не разъезжались,
а в файле вуза одно занятие записывалось одной строкой сразу пятью способами:
`Налоги (практ.зан.) доц. Ибраева С.А.`, а группы стояли колонками.

Из этого выросли три требования, которые определили всё приложение:

1. **Правка не должна ломать расписание.** Ошибка сотрудницы видна сразу
   и откатывается.
2. **Загрузка файла не должна быть молчаливой.** Пропущенная строка или
   неверная неделя — это испорченное расписание у всего вуза.
3. **Приложение должно работать в сети вуза.** Без интернета, без внешних
   сервисов и без постоянных расходов.

## Возможности

### Смотреть

- **Пары** — расписание группы.
- **Преподаватели** — у кого, когда и где занятие.
- **Кабинеты** — чем занят кабинет и кто там ведёт.
- **Замены** — что менялось на этой неделе у конкретного человека.
- **Сегодня** — весь вуз за один день, с 9:00 до последней пары.
- Чётная и нечётная недели хранятся в данных, стрелки переключают неделю
  без перезагрузки.
- Объединённые группы — одной карточкой, одинаковые соседние пары у
  кабинета — одной широкой ячейкой.
- Масштаб кнопками, тёмная тема, печать, русский и узбекский.

### Править

- **Загрузка из файла Excel** одной командой, сначала вхолостую.
- **Черновик перед публикацией:** сотрудница видит результат до того, как
  он появится на сайте.
- **Журнал изменений и откат** любой публикации целиком.
- Мелкие правки прямо в списке: передвинуть пару, объединить две в одну,
  растянуть занятие на две или три пары подряд.

### Не дать испортить

- **Дубли в справочниках не появляются.** «Лекция» и `Лекция  ` — один тип
  занятия, а не два. То же с кабинетами, преподавателями и предметами.
- **Растяжка проверяется до применения.** Если в ту же пару вту же неделю
  встал кто-то ещё, приложение откажется растягивать вместо двойного урока.
- **Одновременные правки замечаются.** Вторая сотрудница получит
  предупреждение, а не затрёт правку первой молча.
- **Пустое поле значит «не трогать».** Для намеренной очистки нужна
  отдельная галочка.

### Выгружать

- Excel и CSV, в том числе по одному преподавателю.
- Пауза 30 секунд между выгрузками, чтобы файл не забрали чаще, чем нужно.
- Защита от формульной инъекции в выгрузке.

## Логика, на которой всё держится

Четыре решения, из которых следует всё остальное.

### Чётность недели хранится в данных, а не вычисляется из календаря

Номера недель вуза и календарные недели не совпадают. 12 октября 2026 года —
это 42-я календарная неделя, но 7-я неделя семестра. Из-за этого занятия
показывались не в те дни, для которых были составлены.

Дата начала семестра задаётся настройкой `SEMESTER_FIRST_MONDAY`, а чётность
считается от неё.

### Публикация идёт через черновик

Публичный сайт нельзя испортить недосмотренной правкой: сначала
предпросмотр, потом сознательное решение, потом запись в журнал. Публикация
хранит снимок «было», поэтому вернуть можно не последнее действие, а всю
публикацию целиком.

### Файл вуза разбирается осторожно

В одной ячейке сразу предмет, тип занятия, должность, фамилия и аудитория,
а группы стоят колонками «код группы / аудитория». Разбор учитывает форму
файла и известные опечатки:

| Что во входном файле | Что получается |
|---|---|
| `(на английском языке) (лекц.)` | тип берётся из **второй** скобки |
| `(лпракт.зан)` — уехавшая скобка | тип всё равно распознаётся |
| `АртиковаЗ.З.` | `Артикова З.З.` |
| `ст. ст. преп. Гулямова А.Н.` | должность одна, предмет без `ст` в конце |
| `9.00-10.20` и `9:05-10:25` в одной паре | берётся самое частое |
| «Кураторский час» | не занятие, в расписание не попадает |

Пропущенные строки считаются и показываются. Противоречие в шапке
останавливает загрузку: тихая ошибка здесь означала бы, что занятия
показаны не в ту неделю.

### Данные проверяются на входе

Битый цвет, дубли в справочниках, конфликт занятий при растяжке, две
одновременные правки — всё отсекается в момент записи. Иначе это всплыло бы
через месяц, когда причину уже не найти.

## Как устроено

```
schedule/
├── models.py                таблицы, нормализованные ключи, валидация
├── grid.py                  сборка сетки: дни, пары, объединения, неделя
├── spans.py                 растяжка пар и проверка, что она допустима
├── drafts.py                черновик, предпросмотр, публикация, откат
├── views.py                 что отвечает на каждый адрес
├── admin.py                 справочники, списки, действия над занятиями
├── analytics.py             сводка по парам для сотрудницы
├── admin_access.py          кому открыт вход в админку
├── exports.py               выгрузка в CSV и XLSX
├── management/commands/
│   └── load_week_schedule.py    разбор файла вуза и загрузка
├── templates/schedule/     шаблоны страниц
├── static/schedule/        стили, скрипты, картинки
└── tests_support/          сборка тестового файла расписания

docs/HANDBOOK.md            памятка по коду
OFFICER.md                  инструкция для сотрудницы
deploy/                     systemd, nginx, инструкция установки
```

## Быстрый старт

```bash
git clone https://github.com/mrdanilov/Platform-for-Plekhanov-University.git
cd Platform-for-Plekhanov-University

python -m venv .venv
.venv/bin/pip install -r requirements.txt      # Windows: .venv\Scripts\pip

.venv/bin/python manage.py migrate
.venv/bin/python manage.py createsuperuser
.venv/bin/python manage.py runserver
```

Открыть <http://127.0.0.1:8000/>. Расписание вносится через админку.

Показать коллегам по локальной сети:

```bash
python tools/show_lan.py      # сам найдёт адрес и напечатает ссылку
```

## Загрузка расписания из файла

Сначала вхолостую — приложение покажет, что собирается записать, и не
тронет базу:

```bash
python manage.py load_week_schedule "расписание.xlsx" --dry-run
```

```
  занятий найдено: 493
  групп: 42
  предметов: 223
  преподавателей: 105
  аудиторий: 24
  недель: чётные недели — 493
  пропущено (кураторский час): 39
  пропущено (без номера пары или времени): 1
  внимание: время пары в файле местами отличается, взято самое частое. Отличия: 4
  пробный запуск: база не менялась.
```

Затем запись:

```bash
python manage.py load_week_schedule "расписание.xlsx"
```

Загружается **неделя**, а не всё расписание: ключ занятия включает чётность,
поэтому неделя 8 добавится к неделе 7, а не затрёт её. Флаг `--replace`
стирает всё расписание целиком — использовать его стоит только осознанно.

## Настройки

Всё задаётся переменными окружения; образец с пояснениями — `.env.example`.

| Переменная | Назначение |
|---|---|
| `DJANGO_SECRET_KEY` | подпись сессий и паролей |
| `DJANGO_ALLOWED_HOSTS` | адреса, которые приложение принимает |
| `DJANGO_DEBUG` | на сервере всегда `0` |
| `DJANGO_ADMIN_ALLOWED_IPS` | кому открыт вход в админку; пусто — только локальная сеть |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | адреса, с которых приходят формы |
| `DJANGO_TRUST_PROTO`, `DJANGO_TRUST_XFF` | доверие к заголовкам обратного прокси |
| `SEMESTER_FIRST_MONDAY` | понедельник первой недели семестра |
| `DJANGO_STATIC_ROOT` | папка для собранной статики |

## Тесты

```bash
python manage.py test schedule
```

936 тестов. Проверяется не только логика, но и то, что тихо ломает
эксплуатацию:

- разбор файла на настоящем файле расписания со склейками и опечатками
  (`schedule/fixtures/example_week.xlsx`);
- отсутствие дублей в справочниках и последствия их появления;
- что черновик не пишет в расписание до публикации, а откат возвращает всё;
- что снаружи админки не существует, а заголовком `X-Forwarded-For` это
  не обходится;
- что `STATIC_ROOT` нельзя указать на папку с базой;
- что схема папок в документации соответствует реальности.

Проверки запускаются на каждом push — см. бейдж выше.

## Безопасность

- Вход в админку **закрыт по умолчанию для адресов из интернета**: страницы
  входа нет вовсе (404, а не 403), кнопка «Войти» там, где входа нет, не
  показывается.
- Адрес берётся из `REMOTE_ADDR`, а заголовку `X-Forwarded-For` верят только
  при явном `DJANGO_TRUST_XFF=1` — иначе ограничение обходилось бы одной
  строкой в запросе.
- Секретный ключ, база и копии базы в репозиторий не попадают.
- Приложение останавливается на старте, если `STATIC_ROOT` указывает на
  папку с базой: иначе файл отдался бы всем, кто откроет `/static/db.sqlite3`.
- Защита от формульной инъекции в выгрузке и от спама в форме обратной
  связи.

Подробно — в [`docs/HANDBOOK.md`](docs/HANDBOOK.md).
