# Расписание — короткая памятка

## Что это

Django-приложение для расписания вуза. Данные вносятся через админку или импортом
из Excel/CSV, публичный вид — главная страница с меню выбора.

## Запуск (Windows, PowerShell)

```powershell
cd C:\Users\Den\timetable
.venv\Scripts\activate
python manage.py runserver
```

Открыть: http://127.0.0.1:8000/

Без активации:

```powershell
cd C:\Users\Den\timetable
.venv\Scripts\python.exe manage.py runserver
```

## Главное меню

Блок расписания виден сразу. По умолчанию сетка **пустая**: дни недели в строках,
пары в колонках на месте, все ячейки пустые — ни одной строки с предметом, пока
не выбран фильтр. Над блоком плашка-подсказка и три кнопки:

| Кнопка | Что делает |
|---|---|
| **Группы** | список групп, выбор — расписание этой группы |
| **Пары** | список пар (1-я, 2-я …), выбор — все занятия этой парой |
| **Преподаватели** | список ФИО, выбор — расписание этого преподавателя |

Список открывается всплывающим окном с поиском. После выбора блок обновляется
подгрузкой, без перезагрузки страницы. Стрелки `«` `»` переключают недели.

Без JavaScript всё работает обычными ссылками: `/?view=group&id=3`,
`/?view=teacher&id=5`, `/?view=pair&id=2`.

  двумя мелкими строками подписи; при 34px они превращались в 4px и не читались.
  Файлы обрезаны по контенту, из блока надписи взято только крупное «РЭУ.РФ»
- Надпись перекрашена в белый (`plekhanova_wordmark_white.png`): тёмно-синие буквы
  на синей полосе не видны. Тёмно-синий вариант остался для светлого фона —
  `plekhanova_wordmark.png`
- Полный лок-ап со всеми надписями — `plekhanova_logo.png`, для печати и крупных блоков
- Перегенерировать: `python -m pip install pillow && python tools/make_logo.py`
- Навигация: Главная, На сегодня, Импорт, Университет
- **Переключатель языка RU / UZ** справа. Ссылка ведёт на `/lang/?lang=uz&next=<адрес текущей
  страницы>`: язык запоминается в cookie на год, а выбранная группа или пара в адресе
  не теряется
- **Кнопка темы** ☾ / ☀ — светлая и тёмная. Выбор хранится в `localStorage`
  и применяется до отрисовки, поэтому страница не мигает
- **Кнопка «Войти»** в крайнем правом углу — ведёт в админку

Надпись белая, поэтому одинаково читается
в обеих темах, а логотип не инвертируется фильтром. У обеих картинок заданы
явные `width`, `height`, `min`/`max` и `flex-basis` — иначе во flex-контейнере герб
вытягивается по высоте и сплющивается по ширине. Высота полосы 82px на десктопе,
на мобильных логотип 32px и 27px.

## Режим «Пары»

Фильтр «Пары» выбирает конкретную пару, поэтому занятия у неё всегда в одной
колонке. Раньше карточки шли вертикальным столбиком в узкой ячейке, а остальные
семь колонок были пустыми — строка растягивалась по высоте, а полезная ширина
падала.

Теперь для этого режима таблица не рисуется вовсе. Дни остаются блоками, а
занятия идут сеткой карточек на всю ширину:

- `grid.cards_mode` в `schedule/grid.py` — переключатель. Он включается только
  для «Пар» (`build_grid(..., cards=True)`) и только когда непустая колонка
  ровно одна. У группы с одной парой в неделю привычная таблица сохраняется
- Шаблон `schedule/templates/schedule/_cards.html`, подключается из `_block.html`
- Сетка `repeat(auto-fill, minmax(165px, 1fr))`: карточки переносятся по мере
  заполнения, `minmax` не даёт им растянуться нечитаемыми полосами. На
  мобильных `minmax(140px, 1fr)`
- Шапка с номерами пар убрана: пара и её время вынесены в заголовок над
  карточками, сегодняшний день обведён синим
- Время пары печатается в правом нижнем углу каждой карточки в обоих режимах
- Пустая пара (нечётная неделя, пара без занятий) откатывается на обычную
  таблицу — иначе на ней просто нечего было бы показать
- Печать: тени убираются, рамки остаются, блок дня не рвётся между страницами
- Фрагмент `/block/` ведёт себя так же, поэтому смена фильтра без перезагрузки
  показывает ту же раскладку

## Время пары в карточке

Время выводится внутри карточки занятия во всех режимах — и в таблице, и в
сетке карточек:

- Разметка: `<div class="lesson-time">` последним блоком внутри карточки,
  значение берётся из `cell.lesson.lesson_time`, то есть от той же пары,
  а не от первой в списке
- Карточка получает `position: relative`, блок времени — `absolute` с отступом
  8px справа и снизу. Так угол не зависит от высоты карточки
- Шрифт 11px, `font-weight: 600`, цвет `rgba(0, 0, 0, .55)` — одинаково
  читается на светлой заливке предмета в обеих темах и не перекрашивается
  белым в тёмной
- Чтобы время не наезжало на аудиторию, снизу у карточки отступ больше, чем
  сверху (`5px 6px 15px` в таблице, `7px 9px 18px` в сетке), а подписи в
  таблице дополнительно отступлены справа на 46px

## Информация о университете

Отдельная страница `/university/`, пункт «Университет» в шапке. Не модальное окно:
адрес можно отправить ссылкой, страница листается вместе с шапкой и работает без JS.

- Шаблон `schedule/templates/schedule/university.html` наследует общий каркас
  `base.html`, стили — внизу `style.css`
- Слева контакты и карта (iframe Яндекс Карт, `loading="lazy"`, `border-radius`),
  справа форма. Колонки в `grid-template-columns: 1fr 1fr`, на ширине до 900px
  складываются в одну, кнопка растягивается
- Контакты лежат в `schedule/contacts.py`: адрес, два телефона с подписями,
  почта школы и веб-мастера. Подписи переведены в `schedule/i18n.py`
- Форма — обычный POST без JavaScript: при успехе редирект на `?sent=1`,
  при ошибке страница перерисовывается с кодом 400 и подсказкой
- **Проверка человека**: арифметический пример на картинке, как на других
  сайтах. Рисуется на сервере в `schedule/captcha.py` — PNG собирается через
  `zlib` и `struct`, Pillow не нужен. Плюс ссылка «Другой пример» (`?refresh=1`)
- Пример и ответ лежат в сессии, клиенту отдаётся только картинка. Вопрос
  одноразовый: после попытки он удаляется, при ошибке выдаётся новый — иначе
  один пример можно было бы подбирать перебором. Ответ не меньше 2, потому что
  ноль с буквой O путают, а единица угадывается
- Ограничение: арифметическая капча отсекает тупой спам, но не целевой. Если
  форма станет важной, нужна настоящая reCAPTCHA или hCaptcha с ключами сайта
- Обращения сохраняются в модель `ContactMessage` и видны в админке
  («Обращения», с поиском и фильтром по дате). Серверная проверка требует имя,
  корректную почту, текст, согласие и верный ответ на пример; CSRF — штатный
- Длинный ввод обрезается по максимальной длине поля, а не роняет страницу

## Контрастность

Цвета подписей проверяются по WCAG. Мелкий текст (время пары, даты под днями,
нижняя подпись, подпись в списке) использует отдельную переменную
`--muted-strong`, а не общий `--muted`:

| Элемент | Светлая тема | Тёмная тема |
|---|---|---|
| Время пары `08:00` на серой шапке | `#38485a` / `#e7e6e6` — **7.5:1** | `#c4d0dc` / `#2c3844` — **7.6:1** |
| Дата под днём | `#38485a` / `#f2f2f2` — **8.4:1** | `#c4d0dc` / `#26313c` — **8.5:1** |
| Нижняя подпись, подпись в списке | **9.4:1** | **10.3:1** |

Было `--muted: #6b7a8d` — 3.5:1 на шапке и 3.9:1 под днём, то есть ниже порога
WCAG AA 4.5:1. Теперь `--muted: #4a5b6d` (≥5.6:1), мелкие подписи —
`--muted-strong`. Обе темы проверяются тестами: `schedule/test_ui.py` считает
контраст по формуле WCAG и падает, если значение падает ниже 4.5 (AA) или 7.0 (AAA).

## Мобильная версия

| Ширина | Что меняется |
|---|---|
| ≤ 900px | логотип уменьшается, навигация переносится на вторую строку и скроллится |
| ≤ 620px | кнопки фильтров во всю ширину, колонка дней закреплена слева, шапка таблицы прилипает сверху, таблица скроллится по горизонтали, всплывающий список занимает весь экран |
| ≤ 400px | ещё компактнее таблица, у «Войти» скрывается иконка |
| `(hover: none)` | отключается подсветка кнопок при тапе — на мобильных она «залипает» |

Колонка дней закреплена `position: sticky; left: 0` с тенью-разделителем, поэтому
при прокрутке вбок всегда видно, какой это день. Минимальная ширина таблицы —
620px, чтобы колонки не схлопывались в нечитаемые полоски.

## Вид таблицы

Дни в строках (`Понедельник` … `Суббота`), пары в колонках — как в файле
`Расписание_как_на_фото.xlsx`: серые шапки (`#e7e6e6` / `#f2f2f2`), тонкие рамки,
всё по центру. Пустые ячейки помечены классом `slot-empty` и отличаются фоном.

В ячейке видно: предмет, тип, группу (кроме вида «Группы»), преподавателя (кроме
вида «Преподаватели»), аудиторию. Замены помечены красным.

## Админка

Кнопка «Войти» → http://127.0.0.1:8000/admin/

Логин и пароль задаёт администратор при развёртывании. Учётной записи с
паролем по умолчанию в проекте нет — перед выкладкой создай свою:

```powershell
python manage.py createsuperuser
```

Разделы:

| Раздел | Что |
|---|---|
| Занятия | всё расписание; преподаватель, аудитория и тип правятся прямо в списке; массовые действия «сдвинуть день недели ±1» |
| Импорты расписания | журнал: кто, когда и сколько записей загрузил. Только чтение |
| Группы | группы и курсы |
| Преподаватели | ФИО, должность, кафедра, контакты |
| Предметы | название, сокращение, цвет подложки |
| Аудитории | номер, корпус, вместимость |
| Типы занятий | лекция, практика, семинар… |
| Время пар | номер и интервал пары; задаётся один раз |
| Замены | кто вместо кого и на какую дату |

Ссылка «В расписание» из админки: `/admin/schedule/`.

Правило: у группы в один слот (день + пара + чётность) может быть только одно
занятие — об этом сообщает форма.

## Импорт из Excel

Главный формат — сетка как в `Расписание_как_на_фото.xlsx`:

- первая строка: `1` / `8:00 - 9:20`, `2` / `9:30 - 10:50` …
- первый столбец: `Mn`, `Tu`, `Wed`, `Thu`, `Fri`, `Sat` (по-русски тоже понимает)
- в ячейке занятие несколькими строками, порядок не важен:

```
English
EnG4
F. Ruzmetova
1/13
```

Строка `1/13` — счётчик, игнорируется. Аудитория распознаётся по слову
`ауд.` / `каб` / `зал`. Группы, предметы, преподаватели и аудитории создаются
автоматически, если их нет.

Поддерживаются `.xlsx`, `.xlsm`, `.xls` и `.csv` (UTF-8 и Windows-1251).
Второй формат — плоская таблица (Группа; День; Пара; Предмет; Тип; Преподаватель;
Аудитория; Недели).

Загрузка двухшаговая: «Проверить файл» — показывает ошибки с номерами строк и
ничего не пишет; «Применить импорт» — записывает. Повторный импорт того же файла
обновляет занятия, а не создаёт дубли.

Одновременно выполняется только один импорт: он берёт файловый замок
(`tmp_import/import.lock`), а второй запрос получает понятное сообщение и не
роняет базу. Замок работает в пределах одного хоста (см. ограничение ниже).

> Файл `Расписание_как_на_фото.xlsx` сейчас пустой — в нём только сетка,
> ни одного занятия. Импорт из него создаст время пар, но не расписание.

## Выгрузка Excel

Кнопка «Excel» в шапке блока. Получается файл в том же формате, что и
шаблон-оригинал. Плюс `/export/timetable.csv` — плоская выгрузка всего расписания.

## Замены

Если преподавателя заменили, занятие уходит из его расписания на эту неделю
и появляется у заменяющего. Дата замены должна совпадать с днём недели занятия.

## Локализация

Словари — `schedule/i18n.py`, языки `RU` и `UZ`. Переведены: меню, дни недели
(полные и короткие), кнопки, заголовки блока и страницы, «Ауд.»/«Xona»,
«замена»/«almashuv», подписи недель.

Проверка языка на любой странице: переключатель в шапке ведёт на `/lang/`,
которая ставит cookie `schedule_lang` и возвращает на ту же страницу —
с выбранной группой, парой или преподавателем. Внешний адрес в параметре `next`
отбрасывается (защита от открытого редиректа).

## Безопасность

Что закрыто и чем это проверяется:

| Что | Как | Тесты |
|---|---|---|
| Импорт расписания | `@staff_member_required` — гость и обычный пользователь получают 302 на логин | `test_access.py` |
| Выгрузка Excel | только для сотрудников | `test_access.py` |
| Шаблон CSV для загрузки | только для сотрудников | `test_access.py` |
| Журнал импортов | модель `ImportLog`, читается в админке, руками не правится | `test_import_log.py` |
| Телефон и почта преподавателя | в публичных страницах не выводятся, в списке берутся только 4 поля | `test_access.py` |
| Живой поиск `/list/` | срез `PICKER_LIMIT = 50`, 30 запросов в минуту с одного IP, дальше 429 | `test_throttle.py` |
| Загрузка файлов | белый список расширений, проверка магических байтов, лимит распаковки | `test_upload_guard.py` |

Что осталось открытым намеренно: расписание группы, пары, преподавателя и
аудитории, а также выгрузка CSV — это публичные страницы, иначе расписание
не откроется анонимно.

Что стоит настроить на сервере:

- `DJANGO_DEBUG=0`, `DJANGO_ALLOWED_HOSTS=example.uz`,
  `DJANGO_CSRF_TRUSTED_ORIGINS=https://example.uz` — тогда автоматически
  включаются HTTPS-редирект, Secure-куки и HSTS
- `DJANGO_TRUST_XFF=1`, только если nginx гарантированно переписывает
  `X-Forwarded-For`. Иначе за прокси у всех один IP и лимит `/list/` считает
  всех вместе
- Лимиты в nginx надёжнее кэша Django: последний по умолчанию локальный,
  при нескольких воркерах счётчики разъезжаются

## Ограничение развёртывания: одна реплика

Приложение рассчитано на **один хост и один воркер**. Это осознанное решение
для сайта одного вуза, а не недоработка:

- rate limit `/list/` считает запросы в `LocMemCache` — памяти процесса;
- «Применить импорт» читает проверенный файл из локального `tmp_import`, а
  очередь импорта держится файловым замком на том же диске;
- база — SQLite, запись блокируется целиком.

При нескольких воркерах лимит умножается на их число, импорт ломается, а
SQLite отвечает `database table is locked`. Если понадобится несколько
реплик или воркеров, нужен переезд на PostgreSQL и общий кэш (Redis или
Memcached) — см. задачу `05` в `audit_todos/`.
